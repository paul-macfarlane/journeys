**What to build:** the smaller editor conveniences a writer who lives on the canvas will reach for.

- **Find a step.** A "Find step" field above the canvas (also opened with Cmd/Ctrl+K on the Journey page) filters Step titles as you type; choosing one selects it and centers the map on it.
- **Duplicate step.** "Duplicate" in the box toolbar and the panel footer copies a Step's title (suffixed " copy"), content, Prompt, and Outcome, with no Choices, places it beside the original, and opens it.
- **Content peek.** Hovering a box (or focusing it) shows the first ~140 characters of its content as plain text in a tooltip so the map can be skimmed without opening every Step.
- **Selected step stays in view.** The panel column is sticky so the selected Step's fields stay beside the map while the page scrolls.
- **Map keyboard basics.** With a box focused: Enter opens it (already), arrow keys move focus to the nearest box in that direction, Escape returns focus to the canvas.
- **Zoom to selection / fit.** A "Fit" control already exists; add "Zoom to step" in the box toolbar.

Not included, recorded as decisions for Paul: **undo/redo** for structural edits (the spec excludes undo; an in-memory history stack of the Draft document with Cmd/Ctrl+Z is a medium change worth its own ticket if wanted) and **collapsing or removing the step list** beyond ticket 16's disclosure.

**Resolved technical decisions (execution, not contract changes):**

- **Find step (D1).** `src/components/journeys/find-step.tsx`: a combobox built on the app's `Input` (no new dependency) — `role="combobox"`, accessible name "Find step" (a visually hidden `<label>`; placeholder "Find step…"), `aria-autocomplete="list"`, `aria-expanded`, `aria-controls` naming the listbox, `aria-activedescendant` naming the active option. The listbox (`role="listbox"`, `aria-label="Steps"`) opens on focus, click, ArrowDown, or typing; it lists every Step as an `option` in map order (`mapOrder(layout)`, already computed by the editor) when the query is empty, and the Steps whose `stepName` contains the query case-insensitively when it is not. Each option's accessible name is the Step's name alone (`aria-label`); the Start and Ending badges the old list carried are decoration inside it, so the old list assertions survive with `option` in place of `listitem`. ArrowDown/ArrowUp move the active option (wrapping), Enter chooses it, a pointer click chooses it (`onMouseDown` prevented so blur does not close the list first), Escape closes the list and a second Escape clears the query; blur closes it. No match: an empty listbox and a "No steps match" line beside it. Choosing calls `onSelectStep(stepId, { center: true })`, closes the list, clears the query, and leaves focus in the field. The field sits at the top of the canvas column, directly above the map, `max-w-sm`; the listbox is absolutely positioned beneath it over the map (`z-20`, `max-h-80`, scrollable). **Cmd/Ctrl+K:** a `keydown` listener on `window` mounted by `DraftEditor` (the Journey page is the only page that mounts it): Meta/Ctrl + `k` (not already `defaultPrevented`) prevents the default and focuses the field, selecting its text.
- **Center on a found Step (D1).** `SelectStepOptions` gains `center?: boolean`. The editor's `locateRequest` becomes `locate: { request: number; center: boolean }` (or an equivalent second prop); the canvas locate effect, when `center` is set, skips its on-map check and always runs `fitView({ nodes: [{ id }], maxZoom: 1, duration: 200 })` — the same move ticket 16's locate makes for an off-map box, so a Step found at fit-all zoom on case-3 is shown readable and centered. Every other opening keeps ticket 16's "leave an on-map box alone" rule.
- **Step list removed (D1).** `src/components/journeys/step-list.tsx` is deleted with its `DraftEditor` mount; the "Steps" `h2` and its summary stay (specs read the heading). `OutcomeList` takes the full width beneath the map (the `md:grid-cols-2` wrapper goes). `openStepList` in `e2e/setup/authoring.ts` becomes `openFindStep(page)` (click the "Find step" combobox, expect the "Steps" listbox visible); every `list "Steps"` read in `draft.spec.ts`, `step-editing.spec.ts`, `publish.spec.ts`, and `canvas.spec.ts` becomes a `listbox "Steps"` / `option` read; `canvas-step-list-follows-map` becomes `canvas-find-step-lists-map-order` (the empty-query listbox's option names equal the boxes sorted top-to-bottom then left-to-right — ticket 16's AC-8 in its new home); `canvas-locate-on-map`'s list half chooses its Step from the listbox instead. README's "pick a step from the list" and "the step list under the map follows the map's own order behind a 'Steps' disclosure" are rewritten for the find field.
- **Duplicate (D2).** `duplicateStep(document, stepId): { document; stepId }` in `src/lib/graph/edit.ts`: a new Step (`crypto.randomUUID()`) whose `title` is the original's followed by `" copy"` (the original trimmed to keep the whole within the schema's 200 characters), `content` a structural copy (`structuredClone`), `prompt` and `outcomeId` copied, `choices: []`, `position: null`; an unknown Step returns the document unchanged with `stepId: ""`. Seam A cases in `edit.test.ts`. The editor's `duplicate(stepId)` applies it and opens the copy with `focusTitle` (the existing fit-on-new-box brings it into view). "Duplicate" is a `Button` in the box toolbar (after "Add next step") and in the panel footer (beside "Make this the start").
- **Zoom to step (D2).** A "Zoom to step" `Button` in the box toolbar, calling `fitView({ nodes: [{ id }], maxZoom: 1.5, duration: 200 })` through `useReactFlow` inside the canvas; no editor plumbing.
- **Content peek (D3).** `contentPreview(content, limit = 140): string` in `src/lib/graph/content.ts` (pure): the text of every paragraph, heading, and list item in document order joined by single spaces, whitespace collapsed, images contributing nothing; longer than `limit` is cut at `limit` and given a trailing `…`. Seam A cases in `content.test.ts`. On the map, each Step box renders a `role="tooltip"` element (a second `NodeToolbar` at `Position.Bottom`, so it neither scales with zoom nor is clipped by the box) visible while the box is hovered or its button focused and hidden otherwise, with the box's problem messages (one per line) first and then the preview, or "No content yet" when the preview is empty; the button's `aria-describedby` names it and its `title` attribute goes (a `title` never showed on focus). No spec reads the old `title`.
- **Map keyboard basics (D3).** `onKeyDown` on the Step box button (placeholders included, both are boxes): ArrowUp/Down/Left/Right prevent the default and move focus to the nearest box in that direction — candidates are boxes whose centre lies strictly on that side of the focused box's centre; score = distance along the axis + 2 × the perpendicular offset; the lowest wins; none means focus stays. The newly focused box, if off the map, is brought on with the same `fitView` move locate makes; the panel's selection does not change (Enter opens, as now). Escape moves focus to the map's own focusable container (the React Flow pane) and clears any arrow selection. Neighbour lookup runs off the `nodes` the canvas already holds, through the actions context.
- **Self-loop side route (N-1, D3).** In `ChoiceEdge`, when `source === target` the dagre points are ignored and the path is hand-built in flow coordinates: down from the source anchor by 24, right to 32 past the box's right edge (`targetX + NODE_WIDTH / 2 + 32`), up to 24 above the box's top, left to the target anchor's x, and down into it; smoothed as every other arrow, label at its midpoint. `layout.ts` and its self-loop test are unchanged.
